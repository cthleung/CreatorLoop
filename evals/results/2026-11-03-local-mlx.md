# 2026-11-03: a local model on my Mac as the ear

**Question:** Can a small open model, running on my laptop with MLX, do the ear's job on the same blind test, close enough to Claude with the same calibrated brief? And how long does it take?

## Setup

- **Gold set and blind file:** The same 48 lines and the same blind file as the [calibrated vs generic run](2026-11-03-calibrated-vs-generic.md): 28 must pass, 14 must fail, 6 unruled, so the 2 runs compare like for like. I've since signed off on all 14 must-fail lines and split P23 into a must-pass and a new must-fail line, F15, so the next run of either reader uses the updated set. The blind file and its answer key live in my novel's private repo. This file only has IDs.
- **Model:** `mlx-community/gemma-4-12B-it-4bit`, Gemma 4 12B instruct, 4-bit weights (affine, group size 64), 6.77 GB on disk, 262,144-token context window.
- **Hardware:** MacBook Air (Mac16,12), Apple M4, 10 CPU cores (4 performance, 6 efficiency), 32 GB unified memory, macOS 26.6.2. The model ran on the GPU.
- **Software:** mlx-lm 0.32.2 and mlx 0.32.4, in a Python 3.14 virtual environment.
- **Brief:** The ear-reader agent's instructions (front matter removed), followed by the full text of everything the agent is told to read before judging: the style guide's 3 voice sections, the voice cards file and the reference list. Then a task note with the same wording the Claude runs got from their caller. Nothing was trimmed. It all goes in as the system turn. The blind file is the user turn, with each line prefixed by its line number.
- **Prompt size:** 8,451 tokens after the chat template (about 25 KB of brief plus the 7.6 KB blind file).
- **Sampling:** 5 runs, temperature 0.7, seeds 1 to 5, at most 2,048 new tokens, thinking mode off.
- **Why thinking was off:** The model's chat template turns thinking on by default. A trial run with it on (seed 99) spent all 2,048 tokens reasoning through the items and never got to its answer. So these runs answer straight away. The Claude runs were agent sessions that read the files themselves, so the 2 setups aren't identical on this point.
- **Comparison:** Claude's 5 runs with the calibrated brief, from the earlier result. `tools/eval_stats.py` for both, plus a count of the items where each side's majority verdict matched.

## Results

| | Local Gemma 4 12B | Claude, calibrated brief |
|---|---|---|
| False alarms on 28 must-pass lines | mean 9% (runs 7% to 11%), 95% interval 0% to 21% | mean 4% (runs 4% to 7%), 95% interval 0% to 12% |
| Catches on 14 must-fail lines | mean 71% (runs 64% to 79%), 95% interval 49% to 91% | mean 87% (runs 86% to 93%), 95% interval 69% to 100% |
| Lines that flipped between runs | 4 of 42 (F05, F12, F13, P23) | 2 of 42 (F13, P24) |
| Must-pass lines flagged | P24 and P25 in all 5 runs, P23 in 3 | P23 in all 5 runs, P24 in 1 |
| Must-fail lines missed in every run | F09, F10, F11 | F10 |

McNemar on majority verdicts, local against Claude:
- **Must-pass lines:** 2 flagged only by the local model, 0 only by Claude, p = 0.5.
- **Must-fail lines:** 0 caught only by the local model, 2 only by Claude, p = 0.5.

**Agreement:** The 2 majority verdicts matched on 38 of the 42 scored lines. The 4 they split on were F09 and F11 (Claude caught them, the local model didn't) and P24 and P25 (the local model flagged them, Claude didn't).

**Unruled lines:** The local model flagged U04 in all 5 runs and U01, U02, U03, U05 and U06 in none. Claude flagged U02, U03 and U04 in all 5 runs.

**Against the generic judge:** For reference, the generic Claude judge from the earlier run had a 5% false-alarm mean and a 67% catch mean. McNemar, local against generic: 2 to 0 on must-pass lines (p = 0.5), 3 to 2 on must-fail lines (p = 1).

**Output:** All 5 runs stopped on their own in the right format, and every flag pointed at a real item line. Each run ended with a tally line, and the tally undercounted its own flags every time (it said 13, 11, 11, 12 and 11 against 15, 14, 13, 14 and 12 actual flags).

Prompt speed dropped after the first run, from 85.7 to about 54 tokens per second (the trial run before these got 103.79). This laptop has no fan, so heat is the likely reason, but I didn't measure it.

## What it says

- **It works, and it's close on most lines:** I gave a 12B model on my laptop the same brief as plain text, and it matched Claude's majority verdict on 38 of 42 lines and kept the output format in every run, which honestly surprised me a little.
- **It's worse on both counts I care about:** It flagged 2 approved lines in every run that Claude left alone, and missed 2 more of the must-fail lines. With only 2 lines splitting each way, McNemar can't call either gap real (p = 0.5), so it needs a bigger gold set to say more.
- **It fails the zero-false-alarm bar too, on different lines:** P24 and P25 got flagged in all 5 runs. P23, the line Claude flagged every time, it flagged in 3 of 5.
- **It's far too slow for live drafting:** The median wait for the first token was 151 seconds, against my 8-second target from the [model experiments](../../docs/model-experiments.md). That wait is the model reading the 8,451-token prompt at about 55 tokens per second, and a full answer took a median 197 seconds. It's the same lesson as the Gemma deployment, really: the model can do the job, but a 2-minute wait is the wrong experience for someone mid-scene. A reader that runs while I'm off doing something else is a different story, though, and that's where a local model could already fit.
- **The memory side is easy:** It peaked at 8.64 GB on a 32 GB machine.

## Reproduce

The brief files and the blind test are in my novel's private repo, so the paths below are placeholders.

```
python3.14 -m venv mlxenv && mlxenv/bin/pip install mlx-lm
mlxenv/bin/python tools/local_reader.py --model mlx-community/gemma-4-12B-it-4bit \
    --brief agent.md guide-voice-sections.md voice-targets.md reference-list.md task.md \
    --blind PRIVATE/ear_blind.md --runs 5 --temp 0.7 --seed 1 --max-tokens 2048 --thinking off \
    --out PRIVATE/local
python3 tools/eval_stats.py PRIVATE/ear_key.json --a PRIVATE/local/run1.md PRIVATE/local/run2.md \
    PRIVATE/local/run3.md PRIVATE/local/run4.md PRIVATE/local/run5.md \
    --b PRIVATE/runs/A1.md PRIVATE/runs/A2.md PRIVATE/runs/A3.md PRIVATE/runs/A4.md PRIVATE/runs/A5.md \
    --name-a "local gemma-4-12B-it-4bit" --name-b "Claude, calibrated brief"
```

The timings come from `PRIVATE/local/timing.json`, which `local_reader.py` writes next to the runs.
